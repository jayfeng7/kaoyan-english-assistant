# 考研英语助手 RAG 工程与面试手册

用户做完作文批改后，可以追问语法、写作表达或再要一个例句。系统只在这个入口检索原创教学卡片，流式回答可展开对应来源。原评分由已有批改流程生成，追问解释沿用报告分数。

## 60 秒项目介绍

> 我先用 BM25 建立可解释的基线，然后用本地 Qwen3 对卡片做向量编码。关键词适合明确术语和固定搭配，向量适合中英改述，两路结果按排名融合。上线前我把查询改写、关键词门槛、召回和生成拆开评测。一次关键发现是放宽关键词门槛能提高 BM25 召回，但会让无资料的问题也带着无关证据去生成。我保留了门槛，给向量路加余弦筛选，融合后最多送两张卡。22 条项目自标查询上，混合加改写的 Recall@2 为 100%，5 条应弃答全部正确。下一轮重点是独立标注和难负例，而检索结果与答案是否受证据支持分别验收。

## 难点如何定位和解决

| 遇到的现象 | 定位过程 | 解决方案和验证 |
| --- | --- | --- |
| 问「收信人来不来」时，BM25 漏掉邀请回复卡 | 查看单路候选发现主题相同，但查询缺少卡片关键词。反过来，`a university / an hour` 有明显词面信号，纯向量低于阈值 | 引入 Qwen3 向量并用 RRF 融合。开启改写的保留集上，两路单独为 35.3% 和 94.1%，融合后为 100%。见 [检索实验](RAG_EXPERIMENTS.md#保留集结果)。 |
| 放宽关键词后，无资料问题也会召回 | 固定同一语料和查询，只切换关键词门槛。BM25 的 Recall@2 从 35.3% 到 73.5%，正确弃答从 5/5 到 1/5。弱词项命中也会在 RRF 中贡献名次 | 保留关键词门槛并记录消融结果。后续校准关键词置信或候选重排时，召回和弃答一起验收。见 [关键词门槛消融](RAG_EXPERIMENTS.md#关键词门槛消融)。 |
| 「换个例句」缺少检索主题 | 分别跑原始查询和改写查询。只看本轮时，混合模式在三条省略式追问中命中 1 条 | 短追问命中规则时，从近几轮找到一条有实际内容的用户问题，用其补充检索，保留原始会话用于生成。该组达到 3/3。多主题指代仍需新样例。见 [查询处理](../lib/rag/retriever.ts)。 |
| 生成时引用了靠后且不必要的语法卡 | 对照候选顺序、余弦分、实际引用和生成文本，定位到证据筛选阶段。首轮自动评分还漏认了合法例句 `Tom goes` | 保留首张卡，剔除明显落后且没有关键词支持的次要卡。证据总量 27→22，精确率 73.5%→88.2%，召回在同一批样例中保持。修订评分规则后，另跑了 25 次生成对照。见 [回答与引用](RAG_EXPERIMENTS.md#回答与引用)。 |
| 模型更新可能让旧索引和查询向量处在不同空间 | 向量维数相同仍可能来自不同模型版本。生成请求也需要有界等待 | 离线索引保存语料哈希、模型摘要和编码格式，查询前验证版本。异常时产品回退 BM25，严格评测直接报错。见 [向量索引](../lib/rag/vector-index.ts)和[回退测试](../tests/essay-rag-vector.test.ts)。 |
| SSE 可能把引用编号拆在不同数据块里 | 如果逐块识别编号，半个标记会穿过校验 | 在流中过滤编号时暂存不完整后缀，结束事件只附本轮有效资料。引用 ID 可验证，断言是否由证据支持仍需人工判读。见 [引用过滤](../lib/rag/index.ts)和[接口测试](../tests/api.test.ts)。 |

## 常见追问

**为什么不直接部署向量数据库？** 现有 14 张卡片的索引约 305 KB，精确余弦方便复核和重建。达到目标规模后量出搜索阶段的 P95，再把精确 Top K 当参考测 ANN 召回，结合增量更新和权限需求选型。

**为什么按名次融合？** BM25 词项分和向量余弦的尺度不同。RRF 给每路第 `r` 名加 `1/(60+r)`，两路同一 ID 累加。代价是弱命中也可能给候选加分，所以要同时看词项门槛和弃答样本。

**Recall@2 为 100% 能讲成什么？** 只说明本轮 22 条项目自标保留查询上的宏平均。生成对照中无检索和混合都通过 5/5 内容检查，相关引用覆盖为 0/4 和 4/4。下一轮要冻结新的独立标注集，并逐条评判断言与引用的对应关系。

**线上变慢怎么查？** 把向量化、召回、首次 SSE 内容和回答完成分开计时，区分冷启动、向量超时回退和生成变慢。可先用 `ESSAY_RAG_MODE=keyword` 回到关键词检索，并核对模型摘要与索引版本。

**版本如何复现？** 用 Git 标签定位代码和评测数据，按标签重建索引，保存语料哈希、模型摘要和查询集哈希。用 `pnpm rag:eval` 复跑检索，用 `pnpm rag:eval:answer` 固定同一生成模型做对照。源码发布从公开历史派生并通过 CI，个人手册和本地运行资料在开发仓库维护。见 [运行与复测](RAG_EXPERIMENTS.md#运行和复测)和[下一轮路线](RAG_ROADMAP.md#下一轮的优先顺序)。
