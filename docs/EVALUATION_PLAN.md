# 性能与任务评测实施方案

更新：2026-10-26。适用于当前考研英语助手；本文件是实施方案，不表示新增门禁已获批准或已经通过。不接入 RAG、Harness Runtime 或新的评测云服务。沿用 TEST_STRATEGY.md 的首批 24 条、完整目标 160 条，不另起样本数口径。

同日后续已完成并发布：OCR与单页正文选择合并、明确答卷标记的保守快路径、核心报告与按需参考拆分。实测及限制见 DEVELOPMENT.md 顶部“上传与核心批改提速发布”；以下原始诊断和其他候选目标保留，不将其全部视为已落实。

## 1. 当前问题与已确认事实

用户最明显的慢发生在“上传后，正文迟迟不出现”。需要测量从点击上传到正文真正可编辑的全部时间。

当前流程：图片/PDF 本机处理 → 上传 → OCR → 大模型选择正文行 → 显示正文。文字 PDF 不经 OCR，但仍有正文选择调用。扫描 PDF 还需要 PDF 工具加载和页面渲染，OCR 与下一页渲染已流水线化，OCR 请求保持串行及既有 600ms 最小启动间隔。

批改：同一次模型输出含评分、总评、批注、建议、改进版、范文和表达。评分局部校验后提前显示暂评；完整报告校验完成后保存正式结果并展示追问。长参考内容虽折叠，仍已生成。因此“屏幕精简”不等于“模型生成更少”。

10-26 小样本诊断（每个入口各一次，不能计算有代表性的 P95）：

| 指标 | 本机回环 | 维护者电脑经公网 |
|---|---:|---:|
| 约 62KB 合成印刷图片 OCR 请求 | 1887ms | 3653ms |
| 随后模型正文选择 | 1104ms | 1224ms |
| 两请求相加，到正文返回 | 2991ms | 4877ms |
| 1.10MB PDF worker 文件下载 | 87ms | 3737ms |
| 124词合成小作文：首个校验后暂评 | 2510ms | 2485ms |
| 同小作文：完整报告 | 5059ms | 4944ms |

图片诊断不含浏览器压缩、PDF 渲染、手机性能、UI 渲染；worker 下载是独立探针，不应加到图片耗时里，也不等同完整冷启动。OCR Server-Timing 在本轮公网样本显示处理阶段远短于客户端总等待，差额包括传输、代理和客户端开销，不能全部归因于 OCR 供应商或某个代理。

首个诊断脚本把 source 写为 free，批改两次均被 400 拒绝，属于探针错误，不计性能成功；修正为 custom 后另存报告，不覆盖失败。证据仅在本机忽略目录 artifacts/latency-audit-20261026/，不保存回答、OCR 正文、图片 base64 或密钥。

## 2. 先测量，再缩短关键路径

优先补齐以下时间点，使用一次用户操作的 traceId 串联多个 requestId；每个阶段用自身单调时钟计时，不直接相减手机与服务器时间。并行阶段按关键路径计算，不能简单累加。

| 上传链路 | 批改链路 |
|---|---|
| 点击上传、文件大小/页数 | 点击批改、题型/输入词数 |
| 工具加载与缓存命中、页面渲染/压缩 | 输入校验/排队、供应商尝试次数 |
| 上传开始/结束、服务器接收耗时 | 模型首内容到达、首个校验通过评分 |
| OCR token 等待、限流排队、调用 | 首条可读批注、核心报告完成 |
| 正文选择开始/结束、ready/review | 完整报告完成、追问可用、保存结果 |
| 正文可编辑的实际页面时间点 | 取消、超时、格式失败、文本降级 |

线上只记阶段名、时长、大小、状态、版本和匿名关联 ID。标准数据和参考答案离线保管；经授权的评测在内存读取输入/输出供评分，不把学生原文和完整对话写入普通请求日志，不采集隐藏思维链。若将来需要保存脱敏回放片段，先明确授权、保留期与访问范围。

优化候选必须在同一冻结材料上 A/B 验证：

1. **工具加载**：实测冷/暖启动、加载时机和缓存，考虑在用户选择 PDF 时提前加载；不对所有页面无条件预下载。本站 worker 已有缓存策略，不能把“再加缓存”当作已证实收益。
2. **上传**：核对手机实际发出的字节数和耗时，在不丢细小笔画的前提下比较分辨率、压缩和选区。先定位传输，不盲目增加 OCR 并发或降低清晰度。
3. **正文选择**：当前每次上传均额外调用模型。评估高精度规则快路径与存疑模型路径，先测漏正文/误收题干；不因节省请求而把整份试卷直接批改，不改写学生错误。存疑时保留原稿并要求选正文。
4. **批改输出**：优先评估“评分＋关键批注＋两条建议”作为独立、完整、可验证的核心结果；改进版/范文按需生成，核心结果完成后即可追问。这需要明确新的结果 Schema、历史兼容、打印未生成状态和上下文规则，不能靠删除必填字段或把暂评直接保存实现。
5. **供应商/部署**：只有量化证明是供应商排队或公网传输瓶颈后，再比较同题模型或目标部署位置；不先换模型、改超时或迁移服务。

## 3. 评测单元与通过条件

当前是固定多步工作流，可以采用 Agent 的过程与结果评测方法，无须先改造成自主 Agent。一个 case 是一个有预期结果的任务；一次 trial 是在隔离环境从干净状态执行该任务；一次 run 包含一组 case 的全部 trial。成功同时检查结果和必要的流程约束，不强制唯一的调用顺序。

| 层次 | 验证内容 | 评审方式 |
|---|---|---|
| 软件契约 | 分制、档次、合计、字段、文件限制、唯一终态 | 程序规则；现有 Vitest 为基础 |
| OCR | 原始识别 CER/WER、漏行、标点及原始语法保留 | 人工逐字转录；原始与规范化口径分别报告 |
| 正文选择 | 正文行召回率、保留文字精确率、题干污染率、存疑转人工率 | 人工标记同一份 OCR 输出中应保留的行；不要把 OCR 错误混为选择错误 |
| 教学质量 | 评分偏差、分档一致性、错误指控、修改正确且保留原意 | 教师盲评/裁决＋校准后的模型辅助评审 |
| 过程 | 文件→提取→选正文→批改→追问，工具参数、调用次数、取消后不继续调用 | 阶段事件与规则；未来再扩展实际 Agent 工具轨迹 |
| 最终状态 | 有效评分可保存，未完成不造分；追问引用当前作文；历史恢复不串篇 | 真实浏览器/接口结合验证状态，不能仅让模型判断“任务已完成” |
| 安全/边界 | 页眉或正文中的提示注入、异常文件、限流、超时、供应商失败 | 固定对抗样本、故障注入；真实与 mock 分开 |
| 体验/资源 | 到正文、首评、完整结果、追问可用、成本、字节、调用次数 | 客户端与服务端分阶段测量、真实设备走查 |

正文选择有两套互补评测：用冻结 OCR 文本独立测选择器；用照片→最终正文测端到端。另用人工转录正文与 OCR 正文对同题评分，量化识别错误引起的评分变化。评分比较只在输入确为同一篇文章时进行。

## 4. 数据从哪里来

核心标准集优先来自获准使用的真实考研练习，而非通用榜单或模型生成范文。

| 来源 | 用途 | 限制 |
|---|---|---|
| 用户/受邀同学主动提供的练习、照片、原失败 PDF | 真实字迹、网络/版面、考研评分和完整流程 | 逐份确认评测授权、去标识；评测用途不自动含训练、公开发布或 RAG |
| 教师/教研合作的小批标注 | 四种题型、不同档次与扣分依据 | 先盲评再看 AI；有条件双评与裁决，至少单评加复核 |
| 现有授权/本地使用题库及参考资料 | 题干、配图、阅读定位和答案核对 | 题目不是学生作文；现有答案要人工核对，不自动是真值或可公开材料 |
| 已有6份公开 OCR/PDF材料 | 文件协议、不同字迹和难例回归 | 见 PUBLIC_EVAL_DATASET.md；AI 临时转录不可当人工 CER 真值 |
| [ASAP-AES 官方竞赛](https://www.kaggle.com/c/asap-aes/overview) | 通用自动作文评分流程、按题目分组与 QWK 对照 | 不同题目/分制，不能直接线性换算成考研20/15/10分；使用前核对竞赛数据条款 |
| [Cambridge FCE](https://researchdatasets.cambridge.org/clc-fce-dataset-v1.0)、[错误检测版](https://researchdatasets.cambridge.org/clc-fce-dataset-for-error-detection) | 学习者作文与错误检测辅助研究 | 官方推荐新版；注册及非商业研究/教育许可，禁止随意再分发，并有商业API数据保留限制；本轮不下载或接入 |
| [IAM 官方入口](https://fki.tic.heia-fr.ch/databases) | 英文手写及已有转录的辅助研究候选 | 官方检索说明为非商业研究；页面本轮直接读取超时，下载前进一步核对具体条款；不代表中国学生考研版面 |
| 人工设计或模型辅助生成的受控变体 | 页眉、页码、题干夹杂、跑题、注入、超长、语法错误 | 明确 synthetic，人工核对预期；与真实材料分开统计，不能给自己生成标准分再宣布准确 |

公开数据只作为辅助对照；最终发布判断以本产品人群、题型和真实拍摄分布为主。不得自动抓取论坛/社交平台的学生作文作为获准数据。

## 5. 数据集落地：复用24→160

| 模块 | 首批 | 完整目标 | 标准答案/标注 |
|---|---:|---:|---|
| 作文 | 8 | 48 | 四种题型；教师档次、分项、总分、关键问题与证据 |
| OCR | 4 | 24 | 至少12个独立手写页面，清晰/困难照片配对；逐字转录与正文行标注 |
| 长难句 | 4 | 24 | 主干/依附、必含语义、可接受译法 |
| 阅读/粘贴/PDF | 4 | 40 | 已校对答案、原文定位、干扰项理由 |
| 多轮对话 | 2 | 16 | 场景上下文、必须引用/不能编造的内容、停止恢复 |
| 路由 | 2 | 8 | 可接受意图集合及草稿状态 |
| 合计 | 24 | 160 | 首批包含在完整目标中 |

当前速度故障从 OCR/PDF 子集优先选取覆盖单页图、可复制 PDF、多页扫描、带题干/页眉的材料；同一页的多张照片共用 pageGroup，不能虚增独立页数。

开发80 / 固定回归40 / 封存盲测40沿用既有方案，以作者、同题变体、同一页面多照片、同篇阅读题分组隔离；分组与分层冲突时记录实际数量，不为了凑整数拆开相关样本。每个模块都应在有足够独立组后覆盖三份集合。

每条数据至少记录：caseId、task、source/license/consentScope、input文件引用及SHA256、writerGroup/promptGroup/pageGroup、slice标签、reference、可接受答案/必须失败的条件、标注者/复核者、split、datasetVersion。小批先用本地 JSON 清单与严格校验，不把私有材料放 public、公开仓库或新增第三方平台。

教师先试标少量样本统一评分尺度，记录教师间分歧再评 AI。OCR 转录保留原作者拼写/语法错误；看不清的部分标记存疑并从严格 CER 分母中按预定规则处理，不让模型猜完当真值。

## 6. 完整运行流程

1. **定义任务与失败级别**：速度、质量、安全分别设阈值；明确最终状态、取消、超时、文本降级、转人工的含义。严重错判与慢但正确分开。
2. **冻结数据与版本**：代码提交/源码指纹、Prompt、模型标识、依赖、OCR参数、数据集、评分器、题型分制；材料授权与参考状态必须可追溯。
3. **评测预检**：使用隔离候选与测试端口；校验凭据可用但不打印；检查评测器期望的真实接口契约。401、400、429、网络错误和模型格式失败分别分类；不为跑分放宽公网限流。
4. **建立基线**：相同设备/材料，单并发先测；本机/公网、冷/暖缓存、图片/文字PDF/扫描PDF及1/3/5页分别统计。记录全部首次结果。
5. **执行 trial**：重置测试浏览器存储与会话，仅操作测试数据；共享题库只读。端到端拿到真实终态，阶段事件供诊断。初期每例3次独立执行，尝试数固定，不因失败追加到成功。
6. **分层评分**：规则先判断；教师复核教学质量；模型仅作辅助。模型评审用具体 pass/fail/uncertain 或随机顺序A/B，先对教师已标样本校准误判率；同一模型再次调用不算独立教师。
7. **统计与归因**：报告首次成功率、各切片分母、P50/P95及样本量、超时/取消率、每成功任务成本、正文污染、评分MAE/档次一致/QWK。小样本展示原始耗时/区间；失败不能从速度分母中静默删除，只报成功请求P95时必须并列失败率。
8. **单变量对照**：同样本成对比较一次改动，固定规则与盲测。速度改善须同时检查正文召回、误收题干、教师认可程度；不能以丢字换快。
9. **回归与发布**：既有软件契约全部通过；冻结集无严重回归；人工核心流程签核。发布到新候选目录，保留旧版和失败结果，不原地覆盖在线构建。
10. **试用反馈闭环**：只采集已获准的阶段指标/反馈；故障复现后补入开发/回归集。封存集若被反复用于调参，就退役并补充新盲测样本；生产新故障不能靠删除旧用例解决。

可靠性同时报告“单次完成比例”与“同一任务3次均完成的比例”；不把多次尝试中最好的一次当成功率。统计置信区间按独立作者/题目/页面组处理，重复运行不能当新增独立作文。

建议工程落点：复用 lib/evaluation/、lib/schemas/evaluation.ts、tests/launch.eval.ts；新增字段集中到 types/index.ts。现有四份合成输入、同模型辅助评审和12次格式成功是起点，尚无冻结教师标准集、完整阶段trace或CI质量门禁。

## 7. 候选目标与执行顺序

以下为待基线验证、待确认的产品目标，不是已达到的性能或教学质量承诺。固定参考设备/网络及清晰≤1MB单页输入；扫码多页与冷启动另报，不能混算。

| 候选目标 | 初始目标 |
|---|---|
| 点击上传→单页正文可编辑 | P50≤4秒，P95≤8秒 |
| 点击上传→3页扫描正文可编辑 | P95≤20秒，冷工具加载另列并计入用户总等待 |
| 点击批改→校验后暂评 | P50≤3秒，P95≤8秒 |
| 点击批改→核心结果有效且可追问 | P95≤15秒；待拆分结果契约后测量 |
| 正文质量 | 正文行召回≥99%、混入非正文字符比例≤1%；同时报告错误自动ready与转人工率 |
| OCR质量 | 清晰组CER≤5%为起始候选，困难组单列；转录未人工冻结不宣称通过 |
| 评分质量 | 延用归一化MAE≤0.10、档差≤1比例≥95%的待确认候选；分四题型，并对照教师间一致性 |
| 格式 | 延用首次结构化≥95%的待确认候选；规则不允许非法分制、错误合计或虚构原文通过 |

实施顺序：先完整分段测量和真实慢文件复现 → 首批24条授权/标注与基线 → 单变量缩短上传/正文选择路径 → 核心结果与按需参考的契约设计和对照 → 扩至160及盲测 → 人工签核与持续回归。RAG、Agent Runtime 与云评测平台不在本轮实施范围。

## 8. 方法来源

- [OpenAI：Agent评测](https://developers.openai.com/api/docs/guides/agent-evals)：从过程记录定位问题，再用数据集与重复运行做回归。
- [OpenAI：Trace grading](https://developers.openai.com/api/docs/guides/trace-grading)：过程与最终结果结合，识别工作流中的具体失败点。本项目仅记录可观察阶段，不采集隐藏推理。
- [OpenAI：评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：目标、数据、指标、对照、持续评测，以及用人工标签校准自动评分器。
- [OpenAI：延迟优化](https://developers.openai.com/api/docs/guides/latency-optimization)：减少不必要请求/生成量、安排依赖与并行、区分实际延迟与可感知等待；收益需在本项目实测。

采用以上方法不意味着迁移当前供应商，或把学生材料上传到这些评测平台。
