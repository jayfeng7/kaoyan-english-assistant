# 第二课：知识单元、分词与BM25检索

这是RAG核心的Retrieval部分。第一课手工指定向量，本课不再手工指定排名：使用文本的真实词频、文档频率和长度计算BM25。还没有调用embedding或生成模型，也没有改产品接口。

## 1. 先理解问题

大模型收到一份长文，不等于它能稳定找到适用的那一句。检索需要先定义可被找到、可独立理解、有出处的知识单元，再确定如何比较问题与这些单元。

本课把10张原创教学卡各作为一个chunk。它们覆盖邀请回复、活动安排、通知、请求、道歉、图表单位、图表对比、图画论证、主谓一致、情态动词。卡片是演示资料，未获教师或独立复核，不宣称权威评分标准。

每张卡包含：`id、documentId、title、composition、genres、kind、text、appliesWhen、doesNotApplyWhen、example`。来源、版本与审核状态记录在语料文件外层，供每个chunk继承。

- `id`定位具体chunk版本，例如`grammar.subject-verb.v1`。
- `documentId`把同一父文档的块关联起来；主谓一致与情态动词同属动词形式文档，但不能混成一条规则。
- `composition/genres`来自已经确认的题型/体裁，用于过滤；`any`允许通用语法跨体裁使用。
- `appliesWhen/doesNotApplyWhen`保留规则边界，防止把“He goes”错误套到“He will go”。
- `example`给正例；正文里可能包含正在纠正的错误表达，未来生成阶段必须识别正反例角色。

当前检索文本为`title + text + appliesWhen + example`，同权计数，不做标题加权；`doesNotApplyWhen`保留用于解释与后续生成，未加入这一版词项索引。这个选择是可比较的实验变量，不是统一标准。

## 2. 切块的重点是保留条件

如果把“通常第三人称单数加-s”和“情态动词后仍用原形”切成无法追溯条件的碎片，检索和生成都可能误用。块过小会丢条件；块过大会混入不相关词、挤占上下文，并影响长度统计。

本批已经是短知识卡，不再机械按字数切一次。后续长资料按标题/段落切块，记录父文档与原位置；再通过实验选择长度和overlap。语义切块、固定token切块、父子块检索都应与这个简单基线比较，而非默认复杂方案更好。

## 3. 分词发生了什么

`bm25.mjs`依次执行：NFKC字符规范化、转小写、`Intl.Segmenter('zh', {granularity:'word'})`中英文分词、去标点和一小组中文停用词。

例如`He GO`与`he go`得到相同词项。`邀请信`可被分为`邀请`和`信`；中文并不是按空格就能可靠切词。本课保留`不`等否定词，也没有把所有英文助动词都当停用词，因为`will/could`正是部分语法查询的关键信息。

尚未实现词干还原、同义词展开或查询改写。因此RSVP不会自动变成“请求回复”，pal不会自动变成friend。ICU版本会影响分词，实验报告记录Node与ICU版本。NFKC和小写仅用于检索副本，不修改作文或知识卡原文。

## 4. BM25怎样计算排名

本课使用正IDF变体，对去重后的查询词项求和：

```text
score(q,d) = Σ IDF(t) × tf(t,d) × (k1+1)
                       / [tf(t,d) + k1 × (1-b+b×|d|/avgdl)]

IDF(t) = ln(1 + (N-df(t)+0.5)/(df(t)+0.5))
```

| 符号 | 本课含义 |
| --- | --- |
| N | 全库文档数，这里10张卡 |
| df | 含这个词的文档数量；一个文档重复10次仍只贡献1个df |
| tf | 这个词在当前文档出现次数 |
| \|d\| / avgdl | 当前文档token数量与全库平均token数量 |
| k1 | 调整词频增加的边际收益；默认1.2 |
| b | 调整长度归一化强度；默认0.75，设0时取消这一项影响 |

IDF让库中少见的匹配词贡献更大；词频部分让重复出现有收益但逐渐饱和；长度项避免较长资料仅靠塞入更多词获得优势。k1设0时，一个匹配词只贡献其IDF，词频不再增加分数。

正IDF形式及常用初始参数可对照[Lucene BM25文档](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html)。本课是可读实现，不保证与Lucene/Elasticsearch的字段范数、分词、分数缩放等细节逐位一致。

### 一个可以手算的例子

三篇等长文档：D1=`apple apple`，D2=`apple banana`，D3=`banana banana`。查询只有`apple`。

```text
N=3，df(apple)=2，avgdl=2，所有文档长度都为2
IDF=ln(1+(3-2+0.5)/(2+0.5))≈0.4700

D1: tf=2 → 0.4700×(2×2.2)/(2+1.2)≈0.6463
D2: tf=1 → 0.4700×(1×2.2)/(1+1.2)≈0.4700
D3: tf=0 → 0
```

重复两次没有得到两倍分数，这是词频饱和的表现。代码测试包含这个手算值，也检查长度归一化、元数据过滤、非法参数和指标分母。

## 5. 过滤与打分是两件事

首期根据已确认体裁筛选候选，再在允许集合内打分。全库N、df与平均长度预先固定，不因每次体裁过滤重新估计。通用语法卡通过`any`保留。

这份10条实现对候选逐文档计算分数，保存tf与df统计；它不是完整的倒排搜索引擎。BM25是打分算法，倒排索引是“词→包含它的文档”的数据结构，两者不能混为一谈。大库可用倒排表缩小词项候选访问范围，而不是改变BM25公式。

## 6. 本次真实运行结果与失败

固定版本`lesson02-v1`，Node v24.20.0、ICU 78.3；10张卡，平均54.1个token。12条查询全部为开发演示，11条有相关卡、1条库内无答案；查询和标签由同一作者设计，未经独立评审，没有封存测试集。

默认过滤后：有答案的11条中，10条首位命中相关材料；Recall@3与Recall@5均为10/11；无答案样例返回空结果1/1。不能把它写成线上准确率90.9%，也不能把无答案的空结果与有答案却没找到混为一谈。

最值得看的失败是Q11：`How do I get an RSVP from a pal?`，预期是邀请信请求回复。

| 模式 | 实际结果 | 原因与边界 |
| --- | --- | --- |
| 不过滤 | 首位图表单位卡，分数约3.7602 | 命中了例句中的`an`和`from`；两个词在小库中df都仅1，因此被赋予较高IDF |
| 过滤invitation/small | 空结果 | 错误体裁被排除，但允许材料中仍没有查询词；过滤没有实现语义理解 |

Q09的`He go to school`则能命中主谓一致卡，因为原串与解释共享词项；这类明确术语也是关键词方法应保留的优势。

Q11意味着两个后续实验：一是检查英文停用词/索引字段，二是在相同卡片与查询上接真实多语embedding。不要为了通过Q11，直接把它的问句塞进目标卡片或加一条专用别名后宣布泛化改善。将来扩充query改写时，应使用新的独立查询比较。

本课保留了首次报告与后续解释报告，路径在忽略目录`artifacts/rag-lesson02/`，每次写入新文件，不覆盖前一次失败。报告包含语料hash、查询hash、参数、分词版本、排名与逐词贡献。

## 7. 运行与阅读顺序

```powershell
# 查看12条开发查询的基线
node learning/rag/02-bm25.mjs

# 查看关闭过滤后的误命中及逐词贡献
node learning/rag/02-bm25.mjs --no-filter --explain Q11

# 看懂原文错误查询的每一项分数
node learning/rag/02-bm25.mjs --explain Q09

# 改一个参数做对照；不同时调整多个变量
node learning/rag/02-bm25.mjs --b 0
node learning/rag/02-bm25.mjs --k1 0

# 单独检索自己的说法
node learning/rag/02-bm25.mjs --query 'He go为什么不对' --genre invitation --composition small

# 验证数学与行为
node --test learning/rag/02-bm25.test.mjs
```

先读`data/lesson02-corpus.json`的主谓一致卡和情态动词卡，确认为什么它们应是两个chunk；再读`tokenize`与`buildIndex`，最后运行`--explain Q09`，把每个term的tf、df、IDF与贡献和总分对应起来。

指标：Recall@K表示找回多少标注相关块；MRR@5是前5名中首个相关块名次倒数的平均；nDCG@3按2/1两级相关性评价前三名排序。无答案样例不进入这三个均值，单独测是否错误推荐。标签本身也可能需要修订，本课指标不是教师知识有效性的证明。

## 8. 本课需要掌握的面试解释

“我先用结构化教学卡建立词项检索基线。中文采用明确分词，保留语法关键字与否定；元数据过滤限定体裁，BM25按IDF、词频饱和与长度归一化排序。一次英文改写只命中了图表里的功能词，过滤虽去掉误召回但产生漏召回。我保留这个失败，下一步用同一数据对照dense检索，区分是词项表示限制还是排序问题。”

上面只能用于介绍本次10卡开发实验，不能声称生产规模或真实提升率。

下一课进入真实embedding：tokenizer→encoder→pooling→归一化，分别编码query和passage，建立真正的语义近邻检索；仍保留本课基线和Q11失败。模型渠道与实际依赖在运行前落实，不预先宣称向量一定胜出。
